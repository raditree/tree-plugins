# tree-plugins

Tree 桌面端的**插件仓库**：核心可以把它拉到本机（`<数据根>/plugins_repo`），
在插件面板里列出可安装条目，并把选中的插件**放到可执行文件同级的 `plugins/`** 后热更新。

这个仓库由 `packages/tree_core/lib/src/plugin/plugin_downloader.dart` 解析，
所以**目录形状与 `plugin.json` 的字段就是合同**：改了这里必须同时改那里的校验，
两边各说各话的结局是"面板列不出来"或"装上去起不来"。

## 目录形状

```
tree-plugins/
├── README.md                  # 本文件
├── hello_panel/               # 一个目录 = 一个插件
│   ├── plugin.json            # 必需：元数据（见下）
│   └── hello_panel_plugin.py  # 插件本体（脚本或二进制；文件名由 plugin.json 指名）
└── <plugin_id>/
    ├── plugin.json
    └── ...
```

- **顶层目录才是一个插件**；子目录、点开头的目录（`.git`）、没有 `plugin.json` 的目录
  一律当"不是插件"跳过（并在诊断里说明为什么跳过，不静默）。
- **只放源与随包分发的可执行文件**，不放构建中间物、不放 `.dart_tool/`、不放依赖目录。
  二进制是插件的一部分（脚本插件则只有 `.py`）。

## `plugin.json` 字段

| 键 | 必需 | 语义 |
|---|---|---|
| `id` | ✅ | **必须等于目录名**；字符集 `[A-Za-z0-9_.-]`，且不能是 `.` / `..`（与核心 `PluginConfigStore` 的 id 校验同一条，防路径穿越） |
| `name` | ✅ | 展示名（面板与详情页读它） |
| `version` | ✅ | 三段数字 `x.y.z`（比大小用来判断"有没有更新"；不是 semver 全集） |
| `description` | | 一句话说明 |
| `files` | ✅ | 要放进 `plugins/` 的文件名列表（**相对本目录**，至少一个；不许含 `..`、路径分隔符或绝对路径） |
| `command` | ✅ | 安装后用来拉起的那个文件名（必须在 `files` 里） |
| `args` | | 启动参数数组（字符串） |
| `suspension` | | `keep` = 声明可挂起（热重启先转储、新一世取回续跑）；留空 = 不可挂起。值域只有这两种，写错会被核心拒 |
| `granularity` | | `team`（缺省）/ `agent` / `session` |
| `scope` | | 实例归属（键白名单 `team_id` / `agent_id` / `session_id` / `mode_key`；留空 = 不限定） |

一个最小例子：

```json
{
  "id": "hello_panel",
  "name": "示例面板插件",
  "version": "0.1.0",
  "description": "演示 stdio 握手 + 一个工具 + 一个左栏面板",
  "files": ["hello_panel_plugin.py"],
  "command": "hello_panel_plugin.py",
  "args": []
}
```

## 安装会发生什么（为什么顺序不是随便排的）

`plugins_repo` 里的东西**不直接被执行**；安装是把它复制到「可执行文件同级的 `plugins/`」
（那正是核心解析 binary 型内置插件的同一批查找目录之一）：

1. 复制到同目录的**临时名**（`.part-<随机>`）——先复制完，不碰旧文件；
2. **确认旧进程已经退出**（Windows 上正在运行的 exe 文件根本删不掉，"先换文件再重启"
   在这台机器上是不成立的顺序）；没确认退出 ⇒ **不换、不动旧文件**，回可读原因；
3. 原子改名覆盖目标；
4. 写/更新一条 `plugins.yaml` 条目并热应用（等价于面板上打开开关那条路）。

任何一步失败 ⇒ 旧文件保持原样 + 清掉临时名 + 回一句人话。核心**不会**为了换文件而
杀进程：显式强杀只有用户在面板上按「强制停止」那一条路（框架不变量，见
`docs/plugin-development.md` §6.7）。

## 怎么加一个插件

1. 建一个目录，写 `plugin.json`（字段见上）与本体；
2. 本地验证：把该目录复制到 `<数据根>/plugins_repo/` 下，在面板点「刷新」，
   列不出来就按面板给的原因改（最常见的是 `id` 与目录名不一致）；
3. 提 PR。构建产物与源混在一起的目录不要提。

## 与主仓库的关系

主仓库（`raditree/Tree`，桌面线）里的 `plugins/` 目录就是**这个仓库的工作区**：
它既在这里被维护，也被核心 `git clone` 到数据根。两边的实现契约都在上面那张字段表里。
